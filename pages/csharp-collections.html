C# Collections & LINQ — Level 3

เจาะลึกโครงสร้างข้อมูลชุด (Collections) และพลังแห่งการคิวรีข้อมูลความเร็วสูงด้วย LINQ ในภาษา C# และ .NET 8
🎯 ระดับ: ⭐⭐ กลาง
⏱️ เวลาเรียน: ~50 นาที
⚡ รางวัล: +100 XP
💻 รองรับ .NET 8 / C# 12
🏭
เปรียบเทียบให้เห็นภาพ: "คลังเก็บของอัจฉริยะและเครื่องกรองน้ำวิเศษ"
ทำความเข้าใจ Collections และ LINQ ผ่านสิ่งของในโลกความเป็นจริง
📦 Collections = ภาชนะจัดเก็บสิ่งของหลากหลายประเภท

ในการเขียนโปรแกรม เรามีข้อมูลจำนวนมากที่ต้องจัดเก็บไว้ในหน่วยความจำ แต่ละงานต้องการ "ภาชนะ" ที่มีคุณสมบัติไม่เหมือนกัน:

  • List<T> เหมือน "ชั้นวางของอเนกประสงค์" — วางของเรียงกัน ปรับความยาวได้อัตโนมัติ ชี้หยิบตามลำดับช่องที่ 0, 1, 2 ได้ทันที
  • Dictionary<TKey, TValue> เหมือน "สมุดพจนานุกรม หรือตู้ล็อกเกอร์ที่มีป้ายชื่อ" — แปะคีย์รหัสไว้ อยากได้ของชิ้นไหน แค่บอกชื่อคีย์ก็หยิบได้ในเสี้ยววินาที ($O(1)$) โดยไม่ต้องเปิดดูทีละตู้
  • HashSet<T> เหมือน "ถุงลูกบอลวิเศษ" — ใครโยนลูกบอลลายซ้ำลงไป มันจะดูดกลืนทิ้งอัตโนมัติ รับประกันว่าของข้างในจะไม่ซ้ำกันเลยแม้แต่ชิ้นเดียว
  • Queue<T> เหมือน "แถวคิวกดบัตรคิวซื้อชานม (FIFO)" — ใครมาก่อนได้ก่อน ของที่เข้าคิวก่อนจะได้ออกจากคิวไปประมวลผลก่อน
  • Stack<T> เหมือน "กองจานซ้อนกันในร้านอาหาร (LIFO)" — จานที่วางบนสุดทีหลังสุด จะถูกหยิบไปใช้งานก่อน เหมือนฟังก์ชัน Undo ในโปรแกรม
✨ LINQ = เครื่องกรองน้ำและสายพานแปรรูปข้อมูลวิเศษ

เมื่อเรามีคลังของ (Collections) มหาศาล ถ้าเป็นยุคเก่า เราต้องเขียน loop for / foreach ซ้อน if-else นับสิบบรรทัดเพื่อคัดแยกของ
แต่ LINQ (Language Integrated Query) ทำหน้าที่เป็นท่อกรองน้ำอัจฉริยะ คุณแค่สั่งว่า:
"กรองเอาเฉพาะสินค้าที่ราคา > 100 บาท, เรียงจากขายดีไปน้อย, แล้วหยิบมาแค่ 5 อันแรก" — ทำทั้งหมดนี้เสร็จได้ใน บรรทัดเดียว!

01

Generic Collections ใน C# (.NET)

รู้จักโครงสร้างข้อมูลพื้นฐานที่ใช้บ่อยที่สุดใน System.Collections.Generic

ใน C# ยุคใหม่ เราจะใช้ Generic Collections (มีสัญลักษณ์ <T>) เสมอ เพราะช่วยเรื่อง Type Safety (คอมไพเลอร์ช่วยตรวจสอบประเภทข้อมูลตั้งแต่ตอนเขียนโค้ด) และป้องกันปัญหาประสิทธิภาพจากการทำ Boxing / Unboxing ของ Value Types เมื่อเทียบกับคอลเลกชันยุคเก่าอย่าง ArrayList หรือ Hashtable

📋 Index: O(1) | Search: O(N)
List<T>
อาร์เรย์ยืดหยุ่นปรับขนาดได้อัตโนมัติ (Dynamic Array) เข้าถึงข้อมูลด้วย Index เลขลำดับได้ทันที นิยมใช้เป็นค่าเริ่มต้นสำหรับเก็บข้อมูลแบบรายการทั่วไป
เมธอดหลัก: Add(), AddRange(), Remove(), Contains(), Count
📖 Lookup: O(1) | Add: O(1)
Dictionary<TKey, TValue>
จับคู่ Key กับ Value ด้วยโครงสร้างแบบ Hash Table ค้นหาข้อมูลได้เร็วระดับ $O(1)$ โดยตรงผ่าน Key ห้ามมีคีย์ซ้ำกันในตาราง
เมธอดหลัก: TryGetValue(), ContainsKey(), Remove(), Keys, Values
🎯 Lookup: O(1) | Unique Only
HashSet<T>
เก็บเฉพาะข้อมูลที่ไม่ซ้ำกัน (Set) ตรวจสอบการมีอยู่ด้วย Contains() ได้เร็วระดับ $O(1)$ และรองรับการทำ Set Operations ทางคณิตศาสตร์
เมธอดหลัก: Add(), Contains(), UnionWith(), IntersectWith(), ExceptWith()
🔄 FIFO / LIFO: O(1)
Queue<T> & Stack<T>
Queue<T> ลำดับแบบ FIFO (เข้าก่อนออกก่อน) เหมาะกับคิวงานประมวลผล ส่วน Stack<T> ลำดับแบบ LIFO (เข้าหลังออกก่อน) เหมาะกับระบบ Undo/Redo
เมธอดหลัก: Enqueue/Dequeue (Queue), Push/Pop (Stack), Peek

1.1 การใช้งาน List<T> และ Dictionary<TKey, TValue>

มาดูตัวอย่างการประกาศ เพิ่มข้อมูล และการค้นหาอย่างปลอดภัยในชีวิตจริง:

⚡ CollectionsDemo.cs 
using System;
using System.Collections.Generic;

// ─── 1. List<T>: รายการยืดหยุ่น ───
List<string> products = new() { "โน้ตบุ๊ก", "เมาส์ไร้สาย", "คีย์บอร์ดกลไก" };
products.Add("จอภาพ 4K");
products.Remove("เมาส์ไร้สาย");

Console.WriteLine($"จำนวนสินค้าทั้งหมด: {products.Count}");
Console.WriteLine($"สินค้าชิ้นแรก: {products[0]}"); // เข้าถึงด้วย Index

// ─── 2. Dictionary<TKey, TValue>: ตารางค้นหาด้วยคีย์ ───
Dictionary<string, decimal> priceLookup = new()
{
    { "PROD-001", 25900.00m },
    { "PROD-002", 1290.00m },
    { "PROD-003", 3490.00m }
};

// เพิ่มข้อมูลแบบปลอดภัย (ถ้ามีคีย์อยู่แล้วจะอัปเดต ถ้ายังไม่มีจะเพิ่มใหม่)
priceLookup["PROD-004"] = 14900.00m;

// ⚠️ ข้อควรระวัง: การเรียก priceLookup["INVALID-KEY"] โดยตรงจะโยน KeyNotFoundException!
// ✅ แนวทางปฏิบัติที่ดี: ใช้ TryGetValue ในการค้นหาอย่างปลอดภัย
string searchSku = "PROD-002";
if (priceLookup.TryGetValue(searchSku, out decimal price))
{
    Console.WriteLine($"ราคาของ {searchSku}: {price:N2} บาท");
}
else
{
    Console.WriteLine($"ไม่พบรหัสสินค้า {searchSku} ในระบบ");
}
🖥️ Output: จำนวนสินค้าทั้งหมด: 3 สินค้าชิ้นแรก: โน้ตบุ๊ก ราคาของ PROD-002: 1,290.00 บาท

1.2 การใช้งาน HashSet<T>, Queue<T> และ Stack<T>

ตัวอย่างการกรองค่าที่ไม่ซ้ำด้วย Set และการบริหารจัดการลำดับงานด้วย Queue และ Stack:

⚡ AdvancedCollections.cs 
// ─── 3. HashSet<T>: ป้องกันข้อมูลซ้ำ & เช็ค Contains ได้เร็ว O(1) ───
HashSet<string> activeUserTokens = new();
activeUserTokens.Add("token_abc123");
activeUserTokens.Add("token_xyz789");
bool addedDuplicate = activeUserTokens.Add("token_abc123"); // คืนค่า false เพราะมีอยู่แล้ว

Console.WriteLine($"เพิ่มค่าซ้ำสำเร็จไหม? : {addedDuplicate}"); // false
Console.WriteLine($"Token ออนไลน์ทั้งหมด : {activeUserTokens.Count}"); // 2

// ─── 4. Queue<T>: เข้าก่อน-ออกก่อน (FIFO) เช่น คิวส่งอีเมล ───
Queue<string> emailQueue = new();
emailQueue.Enqueue("welcome_user1@mail.com"); // 1st
emailQueue.Enqueue("invoice_order42@mail.com"); // 2nd

string nextEmail = emailQueue.Dequeue(); // ดึง welcome_user1 ออกมาประมวลผล
Console.WriteLine($"กำลังส่งอีเมลไปยัง: {nextEmail}");

// ─── 5. Stack<T>: เข้าหลัง-ออกก่อน (LIFO) เช่น ระบบ Undo การพิมพ์ ───
Stack<string> actionHistory = new();
actionHistory.Push("พิมพ์: Hello");
actionHistory.Push("พิมพ์: World");
actionHistory.Push("เปลี่ยนสีฟอนต์: Red");

string lastAction = actionHistory.Pop(); // ดึงการกระทำล่าสุดออกเพื่อ Undo
Console.WriteLine($"ยกเลิกคำสั่ง (Undo): {lastAction}"); // เปลี่ยนสีฟอนต์: Red
🖥️ Output: เพิ่มค่าซ้ำสำเร็จไหม? : False Token ออนไลน์ทั้งหมด : 2 กำลังส่งอีเมลไปยัง: welcome_user1@mail.com ยกเลิกคำสั่ง (Undo): เปลี่ยนสีฟอนต์: Red

1.3 ตารางเปรียบเทียบ Time Complexity และ Use Cases

สรุปการเลือกใช้ Collection ให้เหมาะสมกับลักษณะงานเพื่อประสิทธิภาพสูงสุด:

Collection Type Access (Index/Key) Insert / Add Search / Contains จุดเด่น & สถานการณ์ที่ควรเลือกใช้
List<T> O(1) (By Index) O(1) (ท้ายตาราง) O(N) (วนหาทีละตัว) ต้องการเก็บข้อมูลเรียงลำดับ ลูปแสดงผลบนหน้าจอ หรือไม่รู้ขนาดข้อมูลล่วงหน้า
Dictionary<K, V> O(1) (By Key) O(1) (เฉลี่ย) O(1) (ContainsKey) ต้องการค้นหาข้อมูลด้วยรหัส ID, SKU, Username, หรือทำ Caching ในหน่วยความจำ
HashSet<T> N/A (ไม่มี Index) O(1) (เฉลี่ย) O(1) (เช็คการมีอยู่) ต้องการคัดกรองค่าไม่ให้ซ้ำ เช่น แท็กสินค้า, ตรวจสอบสิทธิ์ผู้ใช้, หรือหาเซตผลต่าง
Queue<T> O(1) (Peek หัวแถว) O(1) (Enqueue) O(N) งานประมวลผลตามลำดับก่อน-หลัง เช่น Message Queue, Job Scheduling, Print Spooler
Stack<T> O(1) (Peek ยอดกอง) O(1) (Push) O(N) ระบบย้อนกลับ (Undo/Redo), คำนวณนิพจน์คณิตศาสตร์ (RPN), ประวัติเปิดหน้าเว็บ (Back)
02

Lambda Expressions & Delegates เบื้องต้น

กุญแจสำคัญสู่การเขียน LINQ และ Functional Programming ใน C#

ก่อนที่เราจะใช้ LINQ ได้อย่างเชี่ยวชาญ เราต้องเข้าใจว่า Lambda Expression คืออะไร ในภาษา C# แลมบ์ดาคือ "ฟังก์ชันนิรนาม (Anonymous Function)" ขนาดกะทัดรัดที่สามารถส่งเข้าไปเป็นพารามิเตอร์ของฟังก์ชันอื่นได้ทันที

🔬 ผ่าโครงสร้าง Lambda Expression: x => x.Price > 100

x
Input Parameter
สมาชิก 1 ตัวที่ไหลเข้ามาจาก Collection (C# Infer Type ให้อัตโนมัติ)
=>
Lambda Operator
อ่านว่า "goes to" หรือ "ส่งไปประมวลผลเป็น"
x.Price > 100
Expression / Body
เงื่อนไขหรือการคำนวณที่ต้องการคืนค่า (เช่น คืนค่า true/false)

2.1 Standard Delegates ใน C#: Func vs Action

ในเบื้องหลัง Lambda Expression จะถูกแปลงให้กลายเป็น Delegate (ตัวแทนฟังก์ชันที่มีความปลอดภัยของ Type):

Func<T, TResult>

รับพารามิเตอร์ T และ ต้องคืนค่าผลลัพธ์ เป็น TResult เสมอ (LINQ ส่วนใหญ่ เช่น .Where(), .Select() ใช้ตัวนี้)

Func<int, bool> isEven = n => n % 2 == 0;
Action<T>

รับพารามิเตอร์ T เข้าไปทำงานแต่ ไม่คืนค่าใดๆ กลับมา (void) เหมาะกับงานเช่น Print หรือ Log

Action<string> print = msg => Console.WriteLine(msg);
⚡ LambdaSyntaxDemo.cs 
// ─── 1. พารามิเตอร์เดี่ยว (Single Parameter) ไม่ต้องใส่วงเล็บ ───
Func<int, int> square = x => x * x;
Console.WriteLine($"5 ยกกำลังสอง = {square(5)}"); // 25

// ─── 2. หลายพารามิเตอร์ (Multiple Parameters) ต้องมีวงเล็บ (a, b) ───
Func<int, int, int> add = (a, b) => a + b;
Console.WriteLine($"10 + 20 = {add(10, 20)}"); // 30

// ─── 3. ทำงานหลายบรรทัด (Statement Body) ใช้ปีกกา { ... return ...; } ───
Func<decimal, decimal> calculateVatIncluded = price =>
{
    decimal vatRate = 0.07m;
    decimal vatAmount = price * vatRate;
    return price + vatAmount;
};
Console.WriteLine($"ราคารวม VAT 7% ของ 1,000 บาท: {calculateVatIncluded(1000m)} บาท");
🖥️ Output: 5 ยกกำลังสอง = 25 10 + 20 = 30 ราคารวม VAT 7% ของ 1,000 บาท: 1070.00 บาท
03

LINQ (Language Integrated Query) Methods สำคัญในชีวิตจริง

ประมวลผล คัดกรอง แปลงรูปข้อมูล และสรุปผลในรูปแบบ Fluent Method Chaining

LINQ คือสุดยอดฟีเจอร์ของ .NET ที่เปิดโอกาสให้เรา Query ข้อมูลจาก Collections ใน RAM (LINQ to Objects) หรือส่งคำสั่งแปลงเป็น SQL ไปรันบน Database (Entity Framework Core) ด้วยไวยากรณ์ชุดเดียวกัน!

1. Raw Data
List<Product> 1,000 รายการ
→
2. .Where()
กรองเฉพาะ Price > 500
→
3. .OrderBy()
เรียงตามยอดขายสูงสุด
→
4. .Select()
สกัดเอาเฉพาะ Name, Price
→
5. .ToList()
สร้างผลลัพธ์เป็น List ใหม่
📦 ข้อมูลจำลองสำหรับตัวอย่างทั้งหมดในส่วนนี้:

เราจะใช้ Class Product(int Id, string Name, string Category, decimal Price, int Stock, bool IsActive) ในการทดลอง Query ข้อมูล

3.1 กรองข้อมูล (Filtering) & แปลงข้อมูล (Projection)

.Where() ใช้สำหรับคัดกรองสมาชิกตามเงื่อนไข ส่วน .Select() ใช้สำหรับแปลงรูปร่างของออบเจกต์ (Projection) และ .SelectMany() ใช้สำหรับคลี่ (Flatten) รายการที่ซ้อนกันออกมา:

⚡ FilterAndProject.cs 
record Product(int Id, string Name, string Category, decimal Price, int Stock, bool IsActive);

List<Product> catalog = new()
{
    new(1, "Gaming Laptop", "IT", 39900m, 5, true),
    new(2, "Wireless Mouse", "IT", 890m, 25, true),
    new(3, "Ergonomic Chair", "Furniture", 6500m, 0, false), // สินค้าหมด & ไม่ active
    new(4, "Mechanical Keyboard", "IT", 2990m, 12, true),
    new(5, "Desk Lamp", "Furniture", 750m, 8, true)
};

// ─── 1. .Where(): กรองเฉพาะสินค้า IT ที่พร้อมขาย (IsActive == true และ Stock > 0) ───
var availableIT = catalog
    .Where(p => p.Category == "IT" && p.IsActive && p.Stock > 0)
    .ToList();

// ─── 2. .Select(): สกัดเฉพาะชื่อสินค้าและราคา (แปลงเป็น DTO หรือ Anonymous Type) ───
var priceTags = catalog
    .Select(p => new { p.Name, FormattedPrice = $"{p.Price:N0} บาท" })
    .ToList();

foreach (var item in priceTags)
{
    Console.WriteLine($"🏷️ {item.Name} — {item.FormattedPrice}");
}
🖥️ Output: 🏷️ Gaming Laptop — 39,900 บาท 🏷️ Wireless Mouse — 890 บาท 🏷️ Ergonomic Chair — 6,500 บาท 🏷️ Mechanical Keyboard — 2,990 บาท 🏷️ Desk Lamp — 750 บาท

3.2 ค้นหาตัวแรกและตัวเดียว: First vs FirstOrDefault vs Single vs SingleOrDefault

นี่คือจุดที่โปรแกรมเมอร์พบ Run-time Exception บ่อยที่สุด! มาดูความแตกต่างและกติกาของแต่ละเมธอด:

LINQ Method เมื่อไม่พบข้อมูล (0 รายการ) เมื่อพบข้อมูลพอดี 1 รายการ เมื่อพบข้อมูลหลายรายการ (≥ 2) คำแนะนำการใช้งานจริง
.First() 💥 InvalidOperationException ✅ ได้รายการแรก ✅ ได้รายการแรก ใช้เมื่อมั่นใจ 100% ว่าต้องมีข้อมูลแน่นอน
.FirstOrDefault() 🛡️ คืนค่า null (หรือ default) ✅ ได้รายการแรก ✅ ได้รายการแรก 🌟 นิยมที่สุด! สำหรับการค้นหาที่อาจไม่พบข้อมูล
.Single() 💥 InvalidOperationException ✅ ได้รายการนั้น 💥 InvalidOperationException ใช้ค้นหาข้อมูลที่เป็น Unique แน่นอน (เช่น ค้นหาด้วย Primary Key ID)
.SingleOrDefault() 🛡️ คืนค่า null (หรือ default) ✅ ได้รายการนั้น 💥 InvalidOperationException คาดหวังว่าต้องมีไม่เกิน 1 รายการ ถ้ามีซ้ำถือว่าผิดปกติร้ายแรง
⚡ ElementOperatorsDemo.cs 
// ค้นหาสินค้าตาม ID ด้วย FirstOrDefault (ปลอดภัย ไม่พังเมื่อไม่พบ)
int searchId = 999;
Product? foundProduct = catalog.FirstOrDefault(p => p.Id == searchId);

if (foundProduct != null)
{
    Console.WriteLine($"พบสินค้า: {foundProduct.Name}");
}
else
{
    Console.WriteLine($"⚠️ ไม่พบสินค้า ID: {searchId} (ได้รับค่า null อย่างปลอดภัย)");
}

// .NET 6+ สามารถระบุค่า Default แบบกำหนดเองได้ถ้าไม่เจอ!
Product fallbackProduct = catalog.FirstOrDefault(
    p => p.Id == 999,
    defaultValue: new Product(0, "สินค้าไม่ระบุ", "None", 0m, 0, false)
);
Console.WriteLine($"Fallback Name: {fallbackProduct.Name}");
🖥️ Output: ⚠️ ไม่พบสินค้า ID: 999 (ได้รับค่า null อย่างปลอดภัย) Fallback Name: สินค้าไม่ระบุ

3.3 การตรวจสอบเงื่อนไข (Quantifiers) & รวมค่าทางสถิติ (Aggregation)

กลุ่มเมธอดสำหรับเช็ค bool และการคำนวณตัวเลขทางสถิติ เช่น ยอดรวม, ค่าเฉลี่ย, สูงสุด/ต่ำสุด:

⚡ QuantifiersAndAggregations.cs 
// ─── 1. Any() และ All(): ตรวจสอบความถูกต้อง ───
bool hasOutOfStock = catalog.Any(p => p.Stock == 0); // มีสินค้าชิ้นไหนหมดไหม? -> true
bool allActive = catalog.All(p => p.IsActive);         // สินค้าทุกตัวเปิดขายอยู่ไหม? -> false

Console.WriteLine($"มีสินค้าของหมดหรือไม่: {hasOutOfStock}");
Console.WriteLine($"สินค้าทุกชิ้น Active หรือไม่: {allActive}");

// ─── 2. สรุปผลทางสถิติ (Aggregation) ───
int totalProductCount = catalog.Count();
decimal totalStockValue = catalog.Sum(p => p.Price * p.Stock);
decimal averagePrice = catalog.Average(p => p.Price);
decimal maxPrice = catalog.Max(p => p.Price);

Console.WriteLine($"จำนวนรายการสินค้า: {totalProductCount} ชิ้น");
Console.WriteLine($"มูลค่าสินค้ารวมในสต็อก: {totalStockValue:N2} บาท");
Console.WriteLine($"ราคาเฉลี่ยต่อชิ้น: {averagePrice:N2} บาท");
Console.WriteLine($"สินค้าราคาสูงสุด: {maxPrice:N2} บาท");
🖥️ Output: มีสินค้าของหมดหรือไม่: True สินค้าทุกชิ้น Active หรือไม่: False จำนวนรายการสินค้า: 5 ชิ้น มูลค่าสินค้ารวมในสต็อก: 263,750.00 บาท ราคาเฉลี่ยต่อชิ้น: 10,206.00 บาท สินค้าราคาสูงสุด: 39,900.00 บาท

3.4 การจัดกลุ่ม (GroupBy), เรียงลำดับ (OrderBy) และแบ่งหน้า (Pagination)

สำหรับการทำระบบ API หรือ Dashboard ที่ต้องจัดกลุ่มสินค้าตามหมวดหมู่ และตัดแบ่งข้อมูลเป็นหน้าๆ (Pagination):

⚡ GroupingAndPaging.cs 
// ─── 1. GroupBy(): จัดกลุ่มสินค้าตามหมวดหมู่ (Category) ───
var groupedByCategory = catalog.GroupBy(p => p.Category);

foreach (var group in groupedByCategory)
{
    Console.WriteLine($"\n📁 หมวดหมู่: {group.Key} (จำนวน {group.Count()} รายการ)");
    foreach (var product in group)
    {
        Console.WriteLine($"   - {product.Name} : {product.Price:N0} บาท");
    }
}

// ─── 2. OrderByDescending() + Skip() + Take(): ทำระบบ Pagination ───
int pageNumber = 1; // หน้าที่ 1
int pageSize = 2;   // ดึงหน้าละ 2 รายการ

var pagedProducts = catalog
    .OrderByDescending(p => p.Price) // เรียงจากราคาแพงสุดลงไป
    .Skip((pageNumber - 1) * pageSize) // ข้ามรายการของหน้าก่อนหน้า
    .Take(pageSize)                   // ดึงมาเฉพาะจำนวนหน้าปัจจุบัน
    .ToList();

Console.WriteLine($"\n📄 ผลลัพธ์สินค้าหน้า {pageNumber} (หน้าละ {pageSize} ชิ้น):");
foreach (var p in pagedProducts)
{
    Console.WriteLine($"⭐ {p.Name} — {p.Price:N0} บาท");
}
🖥️ Output: 📁 หมวดหมู่: IT (จำนวน 3 รายการ) - Gaming Laptop : 39,900 บาท - Wireless Mouse : 890 บาท - Mechanical Keyboard : 2,990 บาท 📁 หมวดหมู่: Furniture (จำนวน 2 รายการ) - Ergonomic Chair : 6,500 บาท - Desk Lamp : 750 บาท 📄 ผลลัพธ์สินค้าหน้า 1 (หน้าละ 2 ชิ้น): ⭐ Gaming Laptop — 39,900 บาท ⭐ Ergonomic Chair — 6,500 บาท
04

Deferred Execution vs Immediate Execution

เข้าใจเบื้องหลังการทำงานแบบผัดผ่อน และป้องกันหายนะจาก Multiple Enumeration

หัวใจสำคัญที่ทำให้ LINQ มีประสิทธิภาพสูงคือกลไก Deferred (Lazy) Execution หรือการ "ผัดผ่อนการประมวลผล" คำสั่ง LINQ จะยังไม่เริ่มลูปคำนวณข้อมูลจริงจนกว่าผลลัพธ์นั้นจะถูกร้องขอ (Enumerated)!

⏳

Deferred Execution (Lazy)

คืนค่ากลับมาเป็นโครงสร้าง IEnumerable<T> ยังไม่มีการคำนวณเกิดขึ้นจริงในหน่วยความจำตอนประกาศตัวแปร

.Where(), .Select(), .OrderBy(), .Take(), .Skip()
⚡

Immediate Execution (Eager)

บังคับให้ประมวลผลทันทีและจัดเก็บผลลัพธ์ลงในหน่วยความจำ RAM (Snapshot ณ เวลานั้น)

.ToList(), .ToArray(), .ToDictionary(), .Count(), .First(), .Sum()
⚠️ หลุมพรางอันตราย: ปัญหา Multiple Enumeration

หากคุณส่ง IEnumerable<T> ที่สร้างจาก LINQ ไปใช้หลายครั้ง เช่น เช็ค query.Any() แล้วต่อด้วย query.Count() แล้ววน foreach (var x in query) — LINQ จะวนลูปคำนวณใหม่ทุกครั้ง!

และหาก Query นั้นเชื่อมต่อกับ Database (EF Core) มันจะทำการส่งคำสั่ง SQL ไปยิง Database ใหม่ทุกรอบ ทำให้ระบบหน่วงและช้าลงอย่างมาก
วิธีแก้ไข: ให้เติม .ToList() หรือ .ToArray() ตั้งแต่รอบแรกเพื่อเก็บผลลัพธ์ลงใน RAM

⚡ DeferredExecutionProof.cs 
List<int> numbers = new() { 1, 2, 3 };

// ประกาศ Query แบบ Deferred (ยังไม่คำนวณตอนบรรทัดนี้!)
var query = numbers.Where(n =>
{
    Console.WriteLine($"-> ประมวลผลเลข: {n}");
    return n > 1;
});

Console.WriteLine("เพิ่มเลข 4 และ 5 เข้าไปใน List ต้นฉบับ...");
numbers.Add(4);
numbers.Add(5);

Console.WriteLine("\nเริ่มวนลูป foreach เพื่ออ่านค่า (Enumeration เกิดขึ้นตรงนี้!):");
foreach (var num in query)
{
    Console.WriteLine($"✅ ผลลัพธ์: {num}");
}
🖥️ Output: เพิ่มเลข 4 และ 5 เข้าไปใน List ต้นฉบับ... เริ่มวนลูป foreach เพื่ออ่านค่า (Enumeration เกิดขึ้นตรงนี้!): -> ประมวลผลเลข: 1 -> ประมวลผลเลข: 2 ✅ ผลลัพธ์: 2 -> ประมวลผลเลข: 3 ✅ ผลลัพธ์: 3 -> ประมวลผลเลข: 4 ✅ ผลลัพธ์: 4 -> ประมวลผลเลข: 5 ✅ ผลลัพธ์: 5
