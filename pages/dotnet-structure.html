โครงสร้าง ASP.NET Core & Minimal APIs

เจาะลึกสถาปัตยกรรมของโปรเจกต์ .NET 8/9 ตั้งแต่ไฟล์ Program.cs, Service Container, Configuration ไปจนถึง Folder Structure สำหรับงานจริง

⭐ ระดับ: พื้นฐาน > กลาง ⏱️ เวลา: ~45 นาที ⚡ รางวัล: +100 XP 🏷️ .NET 8 / .NET 9
🏭 เปรียบเทียบให้เห็นภาพ: โรงงานผลิตสินค้าอัตโนมัติ
💡 Analogy

ASP.NET Core Web API เหมือน โรงงานผลิตสินค้าอัจฉริยะ:
• Program.cs คือพิมพ์เขียวและศูนย์ควบคุมการเปิดโรงงาน
• builder.Services (DI Container) คือคลังอะไหล่และช่างเฉพาะทางที่เตรียมไว้พร้อมหยิบใช้งาน
• app (Middleware Pipeline) คือสายพานลำเลียงที่ทุกคำขอ (Request) ต้องวิ่งผ่านด่านตรวจความปลอดภัยก่อนเข้าสู่กระบวนการผลิต
• Endpoints / Controllers คือแผนกผลิตสินค้าที่ส่งสินค้า (Response JSON) กลับไปให้ลูกค้า

01

โครงสร้างโฟลเดอร์ของ Web API ในงานจริง

เมื่อสร้างโปรเจกต์ด้วยคำสั่ง dotnet new webapi เราจะได้โครงสร้างไฟล์พื้นฐาน และนี่คือโครงสร้างที่ทีมพัฒนา .NET นิยมใช้แบ่งสัดส่วน:

📁 Project Directory Tree
MyWebApiProject/
├── 📁 Controllers/         # แหล่งรวม Controller Classes สำหรับจัดการ HTTP Endpoints
│   └── ProductsController.cs
├── 📁 Models/              # Database Entities (ตรงกับ Table ใน Database)
│   └── Product.cs
├── 📁 DTOs/                # Data Transfer Objects (ข้อมูลส่งเข้า/ออกจาก API)
│   ├── CreateProductRequest.cs
│   └── ProductResponse.cs
├── 📁 Services/            # Business Logic & Interfaces
│   ├── IProductService.cs
│   └── ProductService.cs
├── 📁 Data/                # EF Core DbContext และ Migrations
│   └── ApplicationDbContext.cs
├── 📄 appsettings.json     # Configuration หลัก (Connection String, Log Levels)
├── 📄 appsettings.Development.json # ค่า Config เฉพาะตอนรันบนเครื่อง Local
├── 📄 Program.cs           # Entry Point หลักของ Application (.NET 8/9)
└── 📄 MyWebApiProject.csproj # ไฟล์ระบุเวอร์ชัน .NET และ NuGet Packages
02

เจาะลึก Program.cs (Minimal APIs vs Controllers)

ใน .NET 8 และ 9 ไม่มีไฟล์ Startup.cs อีกต่อไป ทุกอย่างรวมอยู่ใน Program.cs ภายใต้ 3 ขั้นตอนหลัก:

📄 Program.cs
using MyWebApiProject.Data;
using MyWebApiProject.Services;
using Microsoft.EntityFrameworkCore;

// ─── 1. สร้าง WebApplicationBuilder ───
var builder = WebApplication.CreateBuilder(args);

// ลงทะเบียน Services ใน Dependency Injection Container
builder.Services.AddControllers(); // สำหรับ Controller-based
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

// ลงทะเบียน EF Core DbContext
builder.Services.AddDbContext<ApplicationDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));

// ลงทะเบียน Business Service
builder.Services.AddScoped<IProductService, ProductService>();

// ─── 2. Build Application ───
var app = builder.Build();

// ─── 3. กำหนด Middleware Pipeline ───
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();
app.UseAuthentication();
app.UseAuthorization();

// ─── 4. Map Endpoints ───
app.MapControllers(); // Map Controllers

// ตัวอย่าง Minimal API Endpoint
app.MapGet("/api/health", () => Results.Ok(new { status = "Healthy", timestamp = DateTime.UtcNow }));

app.Run();
▶ Terminal: info: Microsoft.Hosting.Lifetime[14] Now listening on: https://localhost:7001
💡 ความต่างระหว่าง Minimal APIs กับ Controller-based

• Minimal APIs: เหมาะสำหรับ Microservices ขนาดเล็ก, ฟังก์ชันเร็วๆ ไม่ต้องสร้าง Controller class โค้ดสั้นและ Performance สูงสุด
• Controller-based: เหมาะสำหรับ Enterprise App ขนาดใหญ่ที่มี Endpoints จำนวนมาก แบ่งเป็นหมวดหมู่และจัดการง่ายกว่า

03

การตั้งค่าระบบด้วย appsettings.json

ไฟล์ appsettings.json ใช้เก็บค่า Configuration ต่างๆ เช่น Connection String ของฐานข้อมูล:

📄 appsettings.json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "ConnectionStrings": {
    "DefaultConnection": "Server=tcp:sqlserver.database.windows.net,1433;Database=ShopDB;User Id=dbuser;Password=YourSecurePassword;"
  },
  "JwtSettings": {
    "Issuer": "https://myapp.com",
    "Audience": "https://myapp.com",
    "ExpiryInMinutes": 60
  }
}
🚨 กฎความปลอดภัย White-Hat & Secret Management

ห้าม Commit รหัสผ่าน Database หรือ JWT Secret Key ลงใน Git Repo เด็ดขาด! ในเครื่อง Dev ให้ใช้คำสั่ง dotnet user-secrets และบน Production ให้ใช้ Azure Key Vault หรือ Environment Variables
