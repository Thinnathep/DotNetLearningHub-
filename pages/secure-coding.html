Secure Coding & OWASP Top 10 ใน ASP.NET Core

หลักการความปลอดภัยระดับ White-Hat, การป้องกัน SQL Injection, XSS, CSRF, IDOR, การจัดการ Secrets ด้วย Azure Key Vault และกฎเหล็ก Database-First Security

⭐ ระดับ: กลาง ⏱️ เวลา: ~50 นาที ⚡ รางวัล: +100 XP 🏷️ OWASP / JWT / White-Hat
🏰 เปรียบเทียบให้เห็นภาพ: ปราการป้องกันหลายชั้น (Defense in Depth)
💡 Analogy

• UI Validation: เหมือน ป้ายห้ามเข้าหน้าประตูรั้ว — ช่วยกรองผู้ใช้ทั่วไป แต่แฮกเกอร์สามารถกระโดดข้ามรั้ว (ยิง Postman / cURL ตรงเข้า API) ได้ง่ายดาย!
• API Authorization & Input Sanitization: เหมือน ทหารยามเฝ้าประตูห้องโถง คอยตรวจค้นสัมภาระและขอดูบัตรผ่านตัวจริง
• Database Row-Level Security (RLS) & Constraints: เหมือน ตู้เซฟฝังดินหนาพิเศษ ที่แม้ทหารยามจะเผลอ ตู้เซฟก็จะไม่ยอมเปิดให้ข้อมูลหลุดออกไปเด็ดขาด (Database-First Rule)

01

กฎเหล็ก Database-First Enforcement & Client Bypass

🚨 กฎข้อที่ 1: การซ่อนปุ่มบนหน้าจอไม่ใช่ความปลอดภัยที่แท้จริง!

การใช้ @if (user.IsAdmin) { <button>ลบข้อมูล</button> } บน UI เป็นเพียง "ความสะดวกในการใช้งาน (UI Convenience)" เท่านั้น แฮกเกอร์สามารถกด F12 แก้ DOM หรือส่งคำขอ DELETE /api/users/1 ผ่านเครื่องมือยิง API ได้ทันที!

มาตรการที่ถูกต้อง: ต้องมี [Authorize(Roles = "Admin")] ที่ Controller และมีเงื่อนไขตรวจสอบใน Database (Row-Level Security หรือ Policy) เสมอ

02

แนวทางป้องกันภัยคุกคามยอดฮิตตาม OWASP Top 10

💉 1. SQL Injection

• สาเหตุ: นำ String จาก User มาต่อใน SQL ตรงๆ
• วิธีแก้: ใช้ Entity Framework Core หรือ Parameterized Queries ใน Dapper เสมอ ห้ามใช้ $"SELECT * WHERE name = '{userInput}'"

🌐 2. Cross-Site Scripting (XSS)

• สาเหตุ: ยอมให้ User บันทึก JavaScript Tag <script> ลงฐานข้อมูลแล้วนำไปแสดงผลตรงๆ
• วิธีแก้: ใช้ HTML Encoding อัตโนมัติใน Razor / Blazor (หลีกเลี่ยง @((MarkupString)rawHtml))

🔓 3. Broken Access Control / IDOR

• สาเหตุ: User A เปลี่ยนเลข ID ใน URL เช่น GET /api/invoices/999 เพื่อแอบดูใบเสร็จของ User B
• วิธีแก้: ดึง UserId จาก Claims/JWT Token ที่ผ่านการ Sign แล้ว เสมอ (เช่น WHERE id = reqId AND user_id = currentUserId)

🔑 4. Secrets & Hardcoded Keys

• สาเหตุ: ฝังรหัสผ่าน Database หรือ JWT Secret ในโค้ดหรือ Git Repo
• วิธีแก้: ใช้ dotnet user-secrets ตอนพัฒนา และ Azure Key Vault บน Cloud Production

03

JWT Authentication & Role-Based Access Control (RBAC)

📄 SecureOrdersController.cs
[ApiController]
[Route("api/v1/[controller]")]
[Authorize] // 1. ต้อง Login มี JWT Token ที่ถูกต้องจึงจะเข้าถึงได้
public class OrdersController : ControllerBase
{
    private readonly IOrderService _orderService;

    public OrdersController(IOrderService orderService)
    {
        _orderService = orderService;
    }

    [HttpGet("my-orders")]
    public async Task<IActionResult> GetMyOrders()
    {
        // 2. ดึง UserId ที่ปลอดภัยจาก Claims ใน JWT Token
        var userIdString = User.FindFirstValue(ClaimTypes.NameIdentifier);
        if (!int.TryParse(userIdString, out var currentUserId))
        {
            return Unauthorized();
        }

        var orders = await _orderService.GetOrdersByUserIdAsync(currentUserId);
        return Ok(orders);
    }

    [HttpDelete("{id:int}")]
    [Authorize(Roles = "Admin")] // 3. บังคับสิทธิ์เฉพาะ Role Admin เท่านั้น
    public async Task<IActionResult> DeleteOrder(int id)
    {
        await _orderService.DeleteAsync(id);
        return NoContent();
    }
}
