📍 Task 1: Relational Data & Eager Loading

ระบบดึงสินค้าและหมวดหมู่ (Product & Category)

⚠️ ปัญหาที่มักจะเจอ (The Challenges):
  • N+1 Query Problem: ดึงสินค้ามา 10 ชิ้น แต่โปรแกรมยิงคำสั่ง SQL ไปถามหาหมวดหมู่ซ้ำอีก 10 รอบ ทำให้ฐานข้อมูลทำงานหนักโดยไม่จำเป็น
  • Null Reference Exception: ข้อมูลหมวดหมู่ไม่ติดมาด้วย ทำให้แสดงผลหน้าบ้านเป็น null หรือเกิดข้อผิดพลาด
📄 ProductsController.cs
[HttpGet]
public async Task<IActionResult> GetProducts()
{
    var products = await _context.Products
                           .Include(x => x.Category) // 👈 ใช้ Eager Loading ดึงข้อมูลมาพร้อมกันใน 1 SQL JOIN
                           .AsNoTracking()           // 👈 ปิด Tracking เพิ่มความเร็วใน Read-Only
                           .ToListAsync();
    return Ok(products);
}
🗣️ คำอธิบายภาษาคน (Analogy):

เหมือนไปสั่ง ข้าวขาหมูหน้าร้าน ถ้าไม่ใช้ .Include เราต้องเดินไปสั่งข้าวรอบนึง แล้วเดินกลับมาขอน้ำซุปหมวดหมู่อีกรอบ (วนไปมา 10 รอบ) แต่การใส่ .Include คือการสั่งให้แม่ค้าตักทั้งข้าวและน้ำซุปหมวดหมู่ใส่ถาดเดียวมาเสิร์ฟทันทีในรอบเดียว!

📍 Task 2: Deduplication & Custom Sorting

อัลกอริทึมคัดกรองตัวซ้ำและจัดเรียง (Custom Sorter)

⚠️ ปัญหาและกับดักที่มักจะเจอ (The Challenges):
  • Boundary / Edge Cases: ผู้ใช้ส่งค่าว่าง (""), ส่งค่า null, หรือพิมพ์ยาวเกิน 99 ตัวอักษร
  • Whitespace: ผู้ใช้พิมพ์ "1, 2 , 1" มีช่องว่างคั่น ถ้าไม่ Trim คอมพิวเตอร์จะมองว่า " 2 " != "2"
  • Lexicographical Sort Trap (กับดักการเรียงแบบตัวหนังสือ): ถ้าเรียงแบบ String ข้อความ "10" จะมาก่อน "2" (เพราะอักษร '1' มาก่อน '2') ทำให้ผลลัพธ์ทางคณิตศาสตร์ผิดเพี้ยน
  • Exception Crash: ถ้าใช้ Convert.ToInt32("AA") โปรแกรมจะระเบิดทันทีเมื่อเจอตัวหนังสือ ต้องใช้ int.TryParse เสมอ
📄 DuplicateController.cs
[HttpPost]
public IActionResult CheckDuplicate([FromBody] DuplicateRequest request)
{
    // 1. ดัก Validation ป้องกัน Input ผิดพลาด
    if (request == null || string.IsNullOrEmpty(request.p1))
        return BadRequest("กรุณากรอกข้อมูล");
    if (request.p1.Length > 99)
        return BadRequest("ความยาวเกินกว่า 99 ตัว");

    // 2. ตัด Comma และ Trim ช่องว่าง
    string[] items = request.p1.Split(',');

    // 3. กรองเฉพาะตัวที่ปรากฏซ้ำ (Count > 1)
    List<string> duplicateList = new List<string>();
    foreach (string item in items)
    {
        string cleanItem = item.Trim();
        if (string.IsNullOrEmpty(cleanItem)) continue;

        int count = items.Count(x => x.Trim() == cleanItem);
        if (count > 1 && !duplicateList.Contains(cleanItem))
        {
            duplicateList.Add(cleanItem);
        }
    }

    // 4. แยกกองข้อมูลด้วย int.TryParse (ปลอดภัย ไม่พัง)
    List<string> letterList = new List<string>();
    List<int> numberList = new List<int>();

    foreach (string text in duplicateList)
    {
        if (int.TryParse(text, out int num))
            numberList.Add(num);   // กองตัวเลขแท้
        else
            letterList.Add(text);  // กองตัวอักษร
    }

    // 5. เรียงลำดับตามเงื่อนไข
    letterList.Sort(); // เรียง A-Z
    numberList.Sort(); // เรียงตัวเลขน้อยไปมาก (Numeric Sort)

    // 6. รวมผลลัพธ์: เอาตัวอักษรขึ้นก่อน ตามด้วยตัวเลข
    List<DuplicateResponse> result = new List<DuplicateResponse>();
    foreach (var l in letterList) result.Add(new DuplicateResponse { rank = l });
    foreach (var n in numberList) result.Add(new DuplicateResponse { rank = n.ToString() });

    return Ok(result);
}

📍 Task 3: External API Integration

การเชื่อมต่อระบบภายนอก (HttpClient & Async/Await)

⚠️ ปัญหาที่มักจะเจอ (The Challenges):
  • Blocking I/O (เซิร์ฟเวอร์ค้าง): การยิงขอข้อมูลจากภายนอกแบบ Synchronous ทำให้ Thread ของเซิร์ฟเวอร์หยุดรอ ไม่สามารถรับงานคนอื่นได้
  • Socket Exhaustion (พอร์ตเครือข่ายล้น): สร้าง new HttpClient() เองทุกครั้งจนพอร์ตเชื่อมต่อของระบบปฏิบัติการหมด
  • Payload Format Mismatch: ห่อข้อมูลส่งกลับไม่ตรงตามโครงสร้างที่โจทย์กำหนด (url, method, response)
📄 ExternalApiController.cs
[HttpGet]
public async Task<IActionResult> GetTodo()
{
    string url = "https://jsonplaceholder.typicode.com/todos/1";

    // ยิงคำขอแบบ Asynchronous (Non-blocking I/O) ผ่าน IHttpClientFactory
    var response = await _httpClient.GetAsync(url);
    var content = await response.Content.ReadAsStringAsync();
    var data = JsonSerializer.Deserialize<object>(content);

    // ห่อข้อมูลกลับตามข้อกำหนดมาตรฐาน
    var result = new
    {
        url = url,
        method = "GET",
        response = data
    };

    return Ok(result);
}
🗣️ คำอธิบายภาษาคน (Analogy):

เหมือน "พนักงานหน้าร้านแจกบัตรคิว แล้วส่งไรเดอร์ไปรับของ" ระหว่างที่ไรเดอร์ (HttpClient) เดินทางไปเอาของจากอีกร้าน พนักงานหน้าร้านไม่ต้องยืนนิ่ง สามารถรับออเดอร์ลูกค้ารายถัดไปได้ทันที (async/await) พอน้ำชามาถึงค่อยหยิบใส่กล่องของร้านเราแล้วส่งให้ลูกค้า

🎙️ ตารางดักคอคำถามสัมภาษณ์ (Interview Defense Matrix)

5 คำถามไม้ตายที่กรรมการสัมภาษณ์ชอบใช้ลองของ พร้อมแนวทางตอบแบบมืออาชีพที่แสดงถึงความเข้าใจเชิงลึก:

คำถามที่กรรมการจะลองของ จุดประสงค์ของคำถาม แนวทางการตอบแบบมืออาชีพ
1. ทำไม Task 2 ถึงใช้ int.TryParse? เช็คว่ารู้เรื่อง Exception Handling และ Performance ไหม "เพื่อความปลอดภัยและประสิทธิภาพครับ เพราะ TryParse จะคืนค่า boolean โดยไม่ขว้าง Exception เมื่อเจอตัวหนังสือ ทำให้ระบบทำงานได้ลื่นไหล ไม่เกิด Overhead จาก Exception Handling ครับ"
2. ทำไมต้องแปลงเป็น List<int> ก่อน Sort? เช็คความเข้าใจเรื่อง Data Types และ Lexicographical Ordering "เพื่อป้องกันปัญหาการเรียงแบบตัวอักษรครับ ถ้าเรียงแบบ String เลข '10' จะมาก่อน '2' การแปลงเป็น int ทำให้เรียงตามมูลค่าทางคณิตศาสตร์ที่แท้จริงครับ"
3. ใน Task 1 ถ้าไม่ใส่ .Include จะเป็นอย่างไร? เช็คความเข้าใจเรื่อง ORM, Eager Loading และ N+1 Query "จะทำให้ Category เป็น null หรือถ้าเปิด Lazy Loading ไว้ จะเกิดปัญหา N+1 Query ยิง SQL ซ้ำหลายรอบ การใช้ .Include เป็นการทำ Eager Loading ดึงข้อมูลมาพร้อมกันใน 1 SQL JOIN ครับ"
4. ทำไม Task 3 ต้องใช้ async / await? เช็คความเข้าใจเรื่อง Concurrency และ Web Server Scalability "เป็น Non-blocking I/O ครับ ระหว่างที่รอ Response จาก External API ตัว Thread จะถูกปล่อยคืนสู่ Thread Pool ไปรับคำขอของลูกค้ารายอื่น ทำให้เซิร์ฟเวอร์รองรับ Throughput ได้สูงขึ้นโดยไม่เกิด Thread Starvation ครับ"
5. ข้อสอบชุดนี้มีกระบวนการทำอย่างไร และใช้ AI หรือไม่? วัดความเป็นเจ้าของโค้ด (Ownership) และทัศนคติต่อเครื่องมือ AI "ผมใช้ AI เป็นผู้ช่วยระดมความคิดและขึ้นโครงร่างเบื้องต้นครับ แต่ผมเป็นคนกำหนดตรรกะ ตรวจสอบความถูกต้องของโค้ดทุกบรรทัด ทดสอบ Edge Cases ด้วยตนเอง และเข้าใจการทำงานของสถาปัตยกรรม 100% ครับ"
