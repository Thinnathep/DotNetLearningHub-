💡 เปรียบเทียบให้เห็นภาพจริง (Real-World Analogy)

ลองนึกภาพการขนส่งสินค้าระหว่างประเทศ: เรือเดินสมุทร รถไฟ และรถบรรทุก ต่างมีขนาดและกลไกเครื่องยนต์ที่ต่างกันอย่างสิ้นเชิง แต่ทำไมสินค้าทุกชนิดในโลกถึงถูกขนถ่ายและถ่ายโอนระหว่างกันได้อย่างราบรื่น? คำตอบคือ "ตู้คอนเทนเนอร์มาตรฐานสากล (ISO Shipping Container)"

ในโลกของการพัฒนาซอฟต์แวร์ Backend ของคุณอาจเขียนด้วย C# .NET 8, Mobile App ฝั่งไคลเอนต์เขียนด้วย Swift / Flutter, และระบบปัญญาประดิษฐ์เขียนด้วย Python — หน่วยความจำ RAM และออบเจกต์ในภาษาเหล่านี้จัดเก็บข้อมูลต่างกันโดยสิ้นเชิง แต่เมื่อเราต้องการส่งข้อมูลผ่านอินเทอร์เน็ต (HTTP / TCP / Message Queue) เราจะแปลงออบเจกต์เหล่านั้นให้อยู่ในรูปข้อความมาตรฐาน นั่นคือ JSON หรือ XML เพื่อให้ปลายทางเปิดอ่านและแปลงกลับเป็นออบเจกต์ของภาษาตนเองได้อย่างสมบูรณ์แบบ 100%

01

ตารางเปรียบเทียบหมัดต่อหมัด: JSON vs XML

วิเคราะห์เชิงลึกทั้งไวยากรณ์, ประสิทธิภาพ, ความเข้มงวดของ Schema และสถานการณ์ที่ควรเลือกใช้

ทั้ง JSON (JavaScript Object Notation) และ XML (eXtensible Markup Language) ต่างเป็นรูปแบบข้อความเชิงโครงสร้างที่มนุษย์อ่านเข้าใจ (Human-Readable) และคอมพิวเตอร์ประมวลผลได้ง่าย (Machine-Parseable) แต่มีจุดแข็งและประวัติศาสตร์ที่แตกต่างกันอย่างสิ้นเชิง:

มิติการเปรียบเทียบ JSON XML
1. รูปแบบไวยากรณ์ (Syntax) ใช้รูปแบบ Key-Value Pairs {"key": "value"} และ Array [1, 2, 3] สั้นกระชับ ไม่มีแท็กปิดที่เยิ่นเย้อ ใช้รูปแบบ Nested Tree & Tags คล้าย HTML <user id="1"><name>John</name></user> มีทั้ง Tags และ Attributes
2. ขนาดข้อมูล (Payload Size) เบามาก (Lightweight)
ประหยัด Bandwidth ของเครือข่าย เพราะไม่มี Closing Tags ซ้ำซ้อน เหมาะกับ Mobile App และ Cloud Microservices 		หนักกว่า (Verbose)
มี Overhead ของชื่อแท็กเปิด-ปิด (Closing tags) และการระบุ Namespace ทำให้ขนาดไฟล์เฉลี่ยใหญ่กว่า JSON ราว 20-50%
3. ความเร็วในการประมวลผล (Parsing Speed) เร็วมาก (Fast)
โครงสร้างตรงกับ Memory Object ของภาษาโปรแกรมสมัยใหม่ โดยเฉพาะใน .NET 8 ที่ใช้ Utf8JsonReader ประมวลผลระดับ Zero-Allocation 		ช้ากว่าปานกลาง
ต้องสร้าง Document Object Model (DOM Tree) หรือใช้ Event-based SAX / StAX Stream ในการตรวจสอบโครงสร้างที่ซับซ้อน
4. ชนิดข้อมูล (Data Types) Native Data Types:
รองรับ String, Number, Boolean, Array, Object และ null ในตัวโดยไม่ต้องมี Schema กำกับ 		Text-Based (ทุกอย่างเป็น String):
ตัวเลข วันที่ บูลีน จะถูกมองเป็นตัวหนังสือทั้งหมด เว้นแต่จะระบุ Type ใน XSD Schema หรือแปลงผ่าน Parser
5. การตรวจสอบความถูกต้อง (Schema & Validation) JSON Schema:
มีความยืดหยุ่นสูง กำหนดเงื่อนไขได้กระชับ นิยมใช้ในการตรวจสอบ OpenAPI / Swagger แต่ไม่เคร่งครัดเท่า XSD 		XSD (XML Schema Definition) & DTD:
เข้มงวดสูงสุด
ตรวจสอบโครงสร้าง ความถูกต้องของ Type, ลำดับการปรากฏ, กฎ Regular Expression และบังคับความปลอดภัยได้แน่นหนามาก
6. ฟีเจอร์ขั้นสูงเฉพาะตัว • เรียบง่าย เป็น First-class citizen ของ JavaScript/TypeScript Web
• สนับสนุน JSON-LD และ BSON (Binary JSON) 		• รองรับ Namespaces แยกชื่อข้อมูลไม่ให้ชนกัน
• รองรับ CDATA เก็บข้อมูลดิบ (เช่น HTML / Binary Base64)
• รองรับ XPath & XSLT แปลงเอกสาร XML สู่รูปแบบอื่นได้อัตโนมัติ
7. งานจริงที่นิยมใช้ในปัจจุบัน (Best Use Cases) • RESTful APIs (ASP.NET Core Web API)
• แอปพลิเคชัน Single Page App (React, Vue, Blazor)
• ไฟล์ตั้งค่าใน .NET: appsettings.json
• NoSQL Databases (MongoDB, Cosmos DB) 		• SOAP Web Services & WCF (ระบบธนาคาร/ประกัน/รัฐบาล)
• ไฟล์คอนฟิกโปรเจกต์ .NET: .csproj, web.config
• ระบบชำระเงินระหว่างประเทศ: ISO 20022 & SWIFT
• Single Sign-On Tokens: SAML 2.0
• ไฟล์เอกสาร Microsoft Office (OpenXML .docx, .xlsx)
💡 คำแนะนำในการตัดสินใจสำหรับสถาปัตยกรรมระบบ

หากคุณสร้าง ระบบใหม่ (Greenfield System), Web API หรือ Mobile Backend — JSON คือตัวเลือกอันดับ 1 เสมอ เพราะประสิทธิภาพสูงและพัฒนาได้รวดเร็วกว่า แต่หากต้องเชื่อมต่อกับ ระบบองค์กรขนาดใหญ่ (Legacy Enterprise Integration), ธุรกรรมการเงินข้ามชาติ (ISO 20022), หรือระบบราชการ/ประกันภัยที่บังคับใช้ XSD Schema — XML ยังคงเป็นหัวใจสำคัญที่หลีกเลี่ยงไม่ได้

02

JSON ใน .NET: พลังของ System.Text.Json และ Newtonsoft.Json

เรียนรู้ Serializer ประสิทธิภาพสูงมาตรฐานใหม่ของ .NET 8, การปรับแต่ง Options และ Attributes ที่พบบ่อยที่สุด

⚡
System.Text.Json vs Newtonsoft.Json (Json.NET)
ทำไม Microsoft จึงสร้าง System.Text.Json ขึ้นมาใหม่ใน .NET Core / .NET 8?

ในอดีต .NET Framework พึ่งพาไลบรารีภายนอก Newtonsoft.Json (Json.NET) ของ James Newton-King ซึ่งมีความสามารถรอบตัวและยืดหยุ่นสูงมาก แต่เมื่อเข้าสู่ยุค High-Performance Cloud Native ใน .NET Core / .NET 8 ทาง Microsoft จึงได้พัฒนา System.Text.Json ขึ้นมาเป็น Built-in namespace:

  • Zero / Low Memory Allocation: ทำงานบน ReadOnlySpan<byte> และ Utf8JsonReader อ่านข้อมูล UTF-8 โดยตรงไม่ต้องแปลงเป็น Intermediate String ช่วยลดภาระ Garbage Collection (GC) มหาศาล
  • Speed: เร็วกว่า Newtonsoft.Json เฉลี่ย 2x – 5x เท่า ในการ Serialize และ Deserialize งานทั่วไป
  • AOT Ready (Source Generator): รองรับการสร้างโค้ด Serialization ในขั้นตอน Compile Time ทำให้ทำงานร่วมกับ Native AOT ใน .NET 8 ได้อย่างสมบูรณ์แบบโดยไม่ต้องใช้ Reflection

# 1. การใช้งานพื้นฐาน: Serialize & Deserialize

มาดูตัวอย่างการแปลงระหว่าง C# POCO Class กับ JSON String อย่างง่าย:

📄 JsonBasicsDemo.cs 
using System;
using System.Text.Json;

// 1. กำหนดโครงสร้างข้อมูลด้วย C# Model
public class UserProfile
{
    public int Id { get; set; }
    public string FullName { get; set; } = string.Empty;
    public string Email { get; set; } = string.Empty;
    public bool IsActive { get; set; }
    public decimal Balance { get; set; }
    public string[] Roles { get; set; } = Array.Empty<string>();
}

public class Program
{
    public static void Main()
    {
        var user = new UserProfile
        {
            Id = 1001,
            FullName = "สมชาย สายโค้ด",
            Email = "somchai@dotnet.dev",
            IsActive = true,
            Balance = 15450.75m,
            Roles = new[] { "Developer", "Admin" }
        };

        // 2. C# Object ➔ JSON String (Serialization)
        string jsonString = JsonSerializer.Serialize(user);
        Console.WriteLine("JSON Output:");
        Console.WriteLine(jsonString);

        // 3. JSON String ➔ C# Object (Deserialization)
        string rawInputJson = """
        {
            "Id": 1002,
            "FullName": "สมหญิง มุ่งมั่น",
            "Email": "somying@dotnet.dev",
            "IsActive": true,
            "Balance": 9200.00,
            "Roles": ["Tester"]
        }
        """;

        UserProfile? deserializedUser = JsonSerializer.Deserialize<UserProfile>(rawInputJson);
        Console.WriteLine($"\nแปลงกลับสำเร็จ: ID={deserializedUser?.Id}, ชื่อ={deserializedUser?.FullName}");
    }
}
🖥️ Output: JSON Output:
{"Id":1001,"FullName":"สมชาย สายโค้ด","Email":"somchai@dotnet.dev","IsActive":true,"Balance":15450.75,"Roles":["Developer","Admin"]}

แปลงกลับสำเร็จ: ID=1002, ชื่อ=สมหญิง มุ่งมั่น

# 2. Attributes ยอดฮิตที่ควบคุมโครงสร้าง JSON

ในโลกแห่งความเป็นจริง API ภายนอกมักใช้รูปแบบชื่อแบบ snake_case หรือ kebab-case ในขณะที่ C# ใช้ PascalCase หรือเราอาจต้องการซ่อนข้อมูลความลับ (เช่น Password) ไม่ให้หลุดไปใน JSON เราสามารถควบคุมพฤติกรรมได้ด้วย Attributes ใน System.Text.Json.Serialization:

[JsonPropertyName("name")]
กำหนดชื่อ Key ใน JSON ให้ตรงกับ API ปลายทาง แม้ว่าชื่อ Property ใน C# จะสะกดแบบ PascalCase ก็ตาม
[JsonPropertyName("user_id")]
public int UserId { get; set; }
[JsonIgnore]
ข้าม Property นี้โดยสมบูรณ์ ไม่นำมา Serialize หรือ Deserialize ป้องกันข้อมูลสำคัญรั่วไหล เช่น รหัสผ่าน หรือ Internal Cache
[JsonIgnore]
public string PasswordHash { get; set; }
[JsonInclude]
บังคับให้ Serialize ตัวแปรที่เป็น private / internal หรือ Property ที่มี private setter ซึ่งปกติ System.Text.Json จะมองข้าม
[JsonInclude]
private decimal _internalDiscount;
[JsonIgnore(Condition = ...)]
ข้ามการเขียน Property ลงใน JSON เฉพาะเมื่อค่านั้นมีค่าเป็น null หรือค่า Default ช่วยลดขนาด Payload
[JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]
public string? MiddleName { get; set; }
[JsonNumberHandling]
อนุญาตให้อ่านตัวเลขที่ถูกครอบด้วยเครื่องหมายคำพูด (เช่น "123") หรือเขียนตัวเลขเป็น String ได้อย่างยืดหยุ่น
[JsonNumberHandling(JsonNumberHandling.AllowReadingFromString)]
public int Quantity { get; set; }
[JsonConverter(typeof(...))]
ปรับแต่งการแปลงข้อมูลขั้นสูง เช่น แปลง Enum เป็นข้อความ (JsonStringEnumConverter) หรือจัดรูปแบบวันที่เฉพาะ
[JsonConverter(typeof(JsonStringEnumConverter))]
public OrderStatus Status { get; set; }

# 3. JsonSerializerOptions และการแก้ปัญหาภาษาไทยถูก Escape

การตั้งค่า JsonSerializerOptions ช่วยให้เราควบคุมการทำงานทั้งแอปพลิเคชันได้โดยไม่ต้องแปะ Attribute ทีละตัว:

⚠️ ปัญหาคลาสสิก: ทำไมภาษาไทยกลายเป็น \u0E2A\u0E21\u0E0A\u0E32\u0E22 ใน System.Text.Json?

โดยค่าเริ่มต้นเพื่อความปลอดภัยจาก XSS ทาง System.Text.Json จะทำการ Escape อักขระที่ไม่ใช่ Basic Latin (ASCII) ทั้งหมด! ทำให้ข้อความภาษาไทยถูกแปลงเป็นรหัส Unicode Escaped sequence \uXXXX
วิธีแก้: กำหนด Encoder = JavaScriptEncoder.Create(UnicodeRanges.All) หรือ UnicodeRanges.Thai ใน Options

⚙️ JsonOptionsConfiguration.cs 
using System;
using System.Text.Encodings.Web;
using System.Text.Json;
using System.Text.Json.Serialization;
using System.Text.Unicode;

public class ConfigExample
{
    public static void DemoOptions()
    {
        var model = new
        {
            customer_name = "นายกิตติศักดิ์ พัฒนาระบบ",
            total_price = 24900.50,
            coupon_code = (string?)null, // มีค่าเป็น null
            created_at = DateTime.Now
        };

        // 🌟 ปรับแต่ง JsonSerializerOptions แบบมืออาชีพ
        var options = new JsonSerializerOptions
        {
            // 1. จัดย่อหน้าให้อ่านง่าย สวยงาม (Pretty Print)
            WriteIndented = true,

            // 2. แปลงชื่อ Property เป็น camelCase อัตโนมัติ (เช่น CustomerName ➔ customerName)
            PropertyNamingPolicy = JsonNamingPolicy.CamelCase,

            // 3. ไม่สนใจตัวพิมพ์เล็ก-ใหญ่ตอน Deserialize (เช่น "id", "ID", "Id" อ่านได้หมด)
            PropertyNameCaseInsensitive = true,

            // 4. ไม่ส่งฟิลด์ที่มีค่าเป็น null ออกมาใน JSON ช่วยประหยัด Payload
            DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull,

            // 5. ปลดล็อกภาษาไทย! ป้องกันไม่ให้อักษรไทยกลายเป็น \u0E...
            Encoder = JavaScriptEncoder.Create(UnicodeRanges.All),

            // 6. ยอมรับ Comma ตัวสุดท้ายใน Array / Object ตอน Deserialize
            AllowTrailingCommas = true
        };

        string output = JsonSerializer.Serialize(model, options);
        Console.WriteLine(output);
    }
}

XML ใน .NET: โครงสร้าง, LINQ to XML และ XmlSerializer

เข้าใจองค์ประกอบสำคัญของ XML, การจัดการผ่าน XDocument ยุคใหม่ และการใช้งานจริงในงาน Enterprise

# 1. โครงสร้างและองค์ประกอบหลักของเอกสาร XML

เอกสาร XML มีโครงสร้างเป็น Hierarchical Tree Node ที่ต้องมี Root Element เพียงตัวเดียวเสมอ:

<!-- 1. XML Declaration กำหนดเวอร์ชันและ Encoding -->
<?xml version="1.0" encoding="UTF-8"?>
<Invoice xmlns="http://schemas.company.com/invoice" id="INV-2026-88" status="Approved">
<Customer>
<Name>บริษัท ดอทเน็ต อินโนเวชั่น จำกัด</Name>
<TaxId>0105566001234</TaxId>
</Customer>
<Items>

CDATA (Character Data) คือบล็อกพิเศษใน XML ที่ระบุว่า "ข้อความภายในนี้คือตัวหนังสือธรรมดา อย่าทำการ Parse เป็น Tag"
หากคุณต้องการฝังโค้ด HTML, ข้อความที่มีเครื่องหมายน้อยกว่า <, มากกว่า > หรือแอมเพอร์แซนด์ & โดยไม่ต้องคอยแปลงเป็น &lt;, &gt;, &amp; การครอบด้วย <![CDATA[ ... ]]> จะช่วยป้องกัน XML Parse Exception ได้ทันที

# 2. การสร้างและสืบค้น XML ด้วย LINQ to XML (XDocument)

ใน .NET ยุคใหม่ System.Xml.Linq เป็นเครื่องมือที่ดีที่สุดในการทำงานกับ XML เพราะเขียนโค้ดสั้น ใช้งานร่วมกับคำสั่ง LINQ ได้อย่างทรงพลัง (แทนที่ XmlDocument แบบเก่าใน .NET 2.0):

⚡ LinqToXmlExample.cs 
using System;
using System.Linq;
using System.Xml.Linq;

public class XmlLinqDemo
{
    public static void Run()
    {
        // 🌟 1. สร้าง XML Document ด้วย Functional Construction (อ่านง่ายมาก)
        var xmlDoc = new XDocument(
            new XDeclaration("1.0", "utf-8", "yes"),
            new XElement("Warehouse",
                new XElement("Product",
                    new XAttribute("id", "P001"),
                    new XAttribute("category", "Hardware"),
                    new XElement("Name", "NVMe SSD 2TB"),
                    new XElement("Price", 4500),
                    new XElement("Stock", 15)
                ),
                new XElement("Product",
                    new XAttribute("id", "P002"),
                    new XAttribute("category", "Software"),
                    new XElement("Name", "Visual Studio Enterprise"),
                    new XElement("Price", 42000),
                    new XElement("Stock", 99)
                ),
                new XElement("Product",
                    new XAttribute("id", "P003"),
                    new XAttribute("category", "Hardware"),
                    new XElement("Name", "RAM DDR5 64GB"),
                    new XElement("Price", 7800),
                    new XElement("Stock", 4)
                )
            )
        );

        // 🌟 2. ค้นหาข้อมูลด้วย LINQ Query อันทรงพลัง
        // โจทย์: ค้นหาสินค้าหมวด 'Hardware' ที่มีราคามากกว่า 5,000 บาท
        var expensiveHardware = from prod in xmlDoc.Descendants("Product")
                                where (string)prod.Attribute("category")! == "Hardware"
                                   && (decimal)prod.Element("Price")! > 5000
                                select new
                                {
                                    Id = (string)prod.Attribute("id")!,
                                    Name = (string)prod.Element("Name")!,
                                    Price = (decimal)prod.Element("Price")!
                                };

        Console.WriteLine("=== สินค้า Hardware ราคา > 5,000 บาท ===");
        foreach (var item in expensiveHardware)
        {
            Console.WriteLine($"[{item.Id}] {item.Name} - ฿{item.Price:N0}");
        }

        // 🌟 3. อัปเดตข้อมูลใน XML Node ได้ทันที
        var ssdNode = xmlDoc.Descendants("Product")
                            .FirstOrDefault(p => (string)p.Attribute("id")! == "P001");
        if (ssdNode != null)
        {
            ssdNode.Element("Price")!.Value = "4190"; // ลดราคา
        }
    }
}

# 3. แปลง POCO Class เป็น XML ด้วย XmlSerializer

หากต้องการ Serialize ออบเจกต์ C# ให้กลายเป็น XML แบบอัตโนมัติ เราสามารถใช้ XmlSerializer ร่วมกับ XML Attributes:

📦 XmlSerializerDemo.cs 
using System;
using System.IO;
using System.Xml.Serialization;

// 1. ตกแต่ง C# Class ด้วย XML Serialization Attributes
[XmlRoot("PurchaseOrder", Namespace = "https://ecommerce.example.com/po")]
public class PurchaseOrder
{
    [XmlAttribute("orderNo")]
    public string OrderNumber { get; set; } = string.Empty;

    [XmlElement("OrderDate")]
    public DateTime CreatedDate { get; set; } = DateTime.UtcNow;

    [XmlElement("BuyerName")]
    public string Customer { get; set; } = string.Empty;

    [XmlArray("OrderItems")]
    [XmlArrayItem("Item")]
    public OrderItem[] Items { get; set; } = Array.Empty<OrderItem>();

    [XmlIgnore] // ไม่นำฟิลด์นี้มาบันทึกลง XML
    public string InternalSecretNotes { get; set; } = string.Empty;
}

public class OrderItem
{
    [XmlAttribute("code")]
    public string ProductCode { get; set; } = string.Empty;

    [XmlElement("Quantity")]
    public int Qty { get; set; }

    [XmlElement("Amount")]
    public decimal Price { get; set; }
}

public class SerializerProgram
{
    public static void Main()
    {
        var po = new PurchaseOrder
        {
            OrderNumber = "PO-99412",
            Customer = "นายอนันต์ นพคุณ",
            Items = new[]
            {
                new OrderItem { ProductCode = "SKU-01", Qty = 2, Price = 1500m },
                new OrderItem { ProductCode = "SKU-02", Qty = 1, Price = 3200m }
            }
        };

        var serializer = new XmlSerializer(typeof(PurchaseOrder));
        using var stringWriter = new StringWriter();
        serializer.Serialize(stringWriter, po);

        Console.WriteLine(stringWriter.ToString());
    }
}

# Modern DTO Modeling: ใช้ Positional Records (C# 9+)

ใน .NET 8 การออกแบบ Data Transfer Object (DTO) นิยมใช้ record เพราะเขียนสั้น ได้ความสามารถ Immutability (Read-only) และ Value-equality ในตัว:

💎 ModernDtoPatterns.cs 
using System;
using System.Text.Json.Serialization;

namespace DotNetHub.Dtos;

// 🌟 ตัวอย่างการสร้าง DTO ด้วย Positional Record เขียนแค่บรรทัดเดียว!
public record WeatherForecastDto(
    [property: JsonPropertyName("date")] DateOnly Date,
    [property: JsonPropertyName("temperature_c")] int TemperatureC,
    [property: JsonPropertyName("summary")] string? Summary
)
{
    // คำนวณค่าเพิ่มเติมได้สะดวก
    public int TemperatureF => 32 + (int)(TemperatureC / 0.5556);
}

// 🌟 ซ้อนออบเจกต์ (Nested Records) ได้อย่างคลีน
public record ApiResponseDto<T>(
    [property: JsonPropertyName("status_code")] int StatusCode,
    [property: JsonPropertyName("is_success")] bool IsSuccess,
    [property: JsonPropertyName("message")] string Message,
    [property: JsonPropertyName("data")] T? Data
);
